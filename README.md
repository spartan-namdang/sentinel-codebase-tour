# sentinel-codebase-tour

Slide deck for sharing session 1 of the Sentinel intern program: how a Spartan service is put together, and what one endpoint is made of. Built with Reveal.js: no build step, everything vendored, works offline.

```
sentinel-codebase-tour/
├── README.md
├── tools/check_slides.py      notes structure, ids, colours, text length
└── deck/
    ├── index.html             all slides, one section after another
    ├── css/deck.css           colour tokens (dark default, light override), layouts, diagrams
    ├── js/deck.js             theme switch, footers, animated diagrams, Deck.audit(), Reveal config
    ├── fonts/                 IBM Plex Sans and Mono (woff2)
    └── vendor/reveal.js/      reveal.js 6.0.2 with the notes and highlight plugins
```

## Run it

Serve the `deck/` folder over HTTP (opening `index.html` from disk breaks the speaker view):

```bash
python3 -m http.server 8011 --directory deck
```

Then open <http://localhost:8011>.

| Key | Action |
|---|---|
| `→` `Space` / `←` | Next / previous slide or step |
| `S` | Speaker view: notes, timer, next slide |
| `T` | Switch between the dark (default) and light theme. The choice is remembered. |
| `F` | Full screen |
| `O` | Overview of all slides |

Slide 10 (what review will send back): click a card to open a worked example, the code review sends back next to the code it approves. `←` `→` step through the eight examples, `Esc` closes.

Animated diagrams: click one to pause it. While it is paused, two icons show in its top-right corner: replay restarts it from the beginning, the pause icon (or another click on the diagram) resumes it.

## Structure (75 minutes)

| Part | Slides | Time |
|---|---|---|
| Opening | cover, agenda | 1.5 min |
| Part 1 · How a service is put together | modules, layers, request path, wiring and config, API style, errors, review | 20 min |
| Part 2 · Anatomy of an endpoint | files of an endpoint, DTOs, contract, frontend codegen, error responses, six hops, blocking, HTTP tests (cases, code) | 20 min |
| Live in the repo | Department in Olympus, 7 stops | 20 min |
| Q&A | closing | 15 min |
| Backup | database shape, edges of the service (open only when asked) | — |

Code on the slides uses a made-up `orders` domain written in Olympus idioms (`.left()` / `.right()`, `getOrThrow()`, `@field:` validation, `/api/v1`, `transaction(db.primary)`). The live demo uses the real Department feature; its file paths are in that slide's notes.

  <h4>Dàn ý</h4>
  <ul><li>⏱ 2 phút</li><li>…</li></ul>
  <h4>Full note</h4>
  <p>…</p>

`Dàn ý` is the short outline to glance at; `Full note` is the full script.

## Edit the deck

Every slide uses the same frame: `<section class="l-…" data-section="Part N · …">` with `header.s-head` (eyebrow + `h2`), `div.s-body`, and `aside.notes`. Copy a slide with the layout you need.

- Layouts: `l-cover`, `l-agenda`, `l-part`, `l-cards`, `l-two-col`, `l-figure` (+ `is-stacked`), `l-table`, `l-code` (+ `is-dense`), `l-closing`.
- Colours, sizes and radii come from the tokens at the top of `css/deck.css`. Code blocks use the IntelliJ editor colours (New UI Dark, and Light for the light theme) through the `--code-*` tokens, plus `--code-type` for classes. highlight.js only marks Kotlin declarations, so `deck.js` also tags function calls, class names and enum constants after it runs. No `style="..."` and no colour values in slides; inside SVG use the `.dg` classes.
- Example sheets: give a card `data-example="ex-…"` and put a matching `<article class="ex" id="ex-…">` in the slide's `div.ex-modal` (see slide 10). `deck.js` adds the click and the keys; `Deck.audit()` opens every example and checks it too.
- The footer (`hirespartan.io · <data-section>`) is generated by `deck.js` as the last item of the slide, so it never covers content. Add `data-footer="off"` to a dense slide to drop it.
- Animated diagrams are inline `<svg class="dg dg-anim">`: `data-loop` on the svg or a `g[data-scene]`, dots with `data-along="#path" data-at="…" data-dur="…"`, timed elements with `data-show="start end, …"`. A `.fragment[data-scene="name"]` in the slide switches the diagram to that scene. Path ids are document-wide, so prefix them per diagram (`md-`, `rp-`, `em-`, `fe-`, `er-`, `hp-`). `deck.js` adds the replay and pause controls to every `svg.dg-anim`; they sit just above the drawing when there is room, and `data-tools="above"` on the svg forces that.

After every edit:

```bash
python3 tools/check_slides.py
```

Then open the deck in a browser and run `Deck.audit()` in the console. It walks every slide (with all fragments shown) and lists any body overflow, any code block wider than its box, and anything that reaches into the footer. It must return `[]`.
